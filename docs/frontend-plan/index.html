How standardized it really is

  • About 300 per-component literals and no role layer: #63ADF7 repeated in 8 keys, #121212 in about 10.
  • The new cards hardcode every type size (10–17), tracking and spacing: ContextCard.swift:221-339, NotesWindow.swift:85-106.
  • Motion is per surface: outBack 1.70158 in the panel, easeOut 0.15 in the stamp, 45 ms per caption character.
  • A real bug: the card measures its label in the system font and draws it in Pretendard (BlickyDirector.swift:685 vs BlickyView.swift:134).
  • Old web pages in app/ still carry retired names: --sky-deep #3D9DC3, a beige --paper #EFEBE1.

How the notepads get into a native app

The finals are React with WebGL materials (felt, moss, metal); the shell is SwiftUI. Two ways in; the first is my recommendation.

recommended

A · The finals as they are, in a web view

  • A NotepadPanel.swift: a floating, transparent NSPanel with a WKWebView, one per pad.
  • It loads a built bundle of the two finals (a notepad entry in design/, built into app/shell/notepad/, offline).
  • The shell already holds the data: it passes each card{…} line and turn event in through one call, window.pickje.update(json).
  • Pickle's flight stays native (he's already drawn at the cursor); the pad tells Swift where its sticker is, so he lands on it.
  • Pros: it looks exactly like what you signed off, today. Cons: a web view's memory, and two worlds to keep in step.

B · Port the finals to SwiftUI

  • Rebuild both pads in SwiftUI; bake the felt, moss and metal into images from the design system's own renderer.
  • Pros: one world, native text and scrolling. Cons: days of work before the deadline, and every detail you tuned has to be redone by eye.
